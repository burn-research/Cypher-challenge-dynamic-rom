Submission

Submit a zip archive containing a Python file named model.py that defines a class named model. Any additional Python module you need can be added to the archive (e.g. helper files), but no pretrained weights or extra data are allowed. The sample_code_submission.zip available on the "Files" tab of this competition shows the expected structure and a minimal working baseline. Note: When creating your ZIP archive, include the files themselves rather than the directory that contains them. Otherwise, the submission will fail.

Required interface

Your model class must implement three methods:

  • preprocess(self, data_folder): data_folder is the path to the training data folder (containing one sub-folder per training simulation, each with state.npy and phi.npy). Return any object D you like — it will be passed to fit().
  • fit(self, D): train your model using D. No return value is expected; store the trained parameters as attributes of self.
  • predict(self, test_data_folder): test_data_folder is the path to a single validation/test simulation folder, containing only initial_state.npy (shape (n_features * n_cells,)) and phi.npy (shape (n_timesteps,), the full known forcing trajectory). Return a numpy array of shape (n_features * n_cells, n_timesteps): your forecast of the full flow state at every time step, where column 0 must equal initial_state.npy.

You are free to use any library (PyTorch, TensorFlow, scikit-learn, or plain NumPy) to build your model. Preprocessing, scaling, and the choice of autoregressive vs. direct multi-step forecasting strategy are entirely up to you — the only constraint is the three-method interface above.

Time budget

Each submission (preprocessing + training + inference on all validation/test simulations) has a maximum execution time budget of 6 hours on the challenge infrastructure.

RAM limitations

Because the CodaBench worker has limited RAM, please verify that your model's memory usage remains below 10 GB. Submissions exceeding this limit will not run successfully.
