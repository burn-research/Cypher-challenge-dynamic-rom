Dataset: externally forced 2D laminar flame

The data comes from CFD simulations of 2D transient laminar coflow diffusion flames burning a CH4 and N2 mixture in air, with pulsed/forced inlet velocity. All fields are provided on a common uniform 2D grid, already resampled from the original unstructured CFD mesh.

Flow variables

At every grid cell and time step, the following 11 variables are available:

  • p — pressure
  • U1, U3 — velocity components
  • rho — density
  • T — temperature
  • mix:Q — heat release rate
  • CH4, O2, H2O, CO2, OH — species mass fractions

The forcing signal φ(t)

The inlet velocity profile is modulated in time by a scalar forcing signal φ(t). The bulk inlet velocity at time t is U(t) = U_base · φ(t). φ(t) is provided to you explicitly, alongside the flow state, as an additional input at every time step: it is exactly the information a controller would know in advance, since it defines the boundary condition being imposed on the system.

File format

Every simulation is stored as a folder containing:

  • state.npy — array of shape (n_features * n_cells, n_timesteps), the flattened flow state at every time step (features stacked in the order listed above, each block of n_cells rows corresponding to one feature on the uniform grid).
  • phi.npy — array of shape (n_timesteps,), the forcing signal value at every time step.

A single shared grid.npy file (shape (n_cells, 3), columns x, y, z) gives the coordinates of the uniform grid cells, in case you want to exploit the spatial structure of the domain (e.g. convolutional architectures). The time step is constant and equal to dt = 5e-4 s in every simulation.

Training data

Two simulations, both a frequency "sine sweep" (chirp) from 1 Hz to 80 Hz and back to 1 Hz over 2 s (4000 time steps), at two forcing amplitudes:

  • train/sweep_A0.2 — amplitude A = 0.2
  • train/sweep_A0.4 — amplitude A = 0.4

Validation data (Development phase feedback)

You are given, for each validation case, only the initial snapshot of the state and the full future forcing trajectory φ(t) — never the ground-truth evolution of the state. Your model must forecast the rest of the trajectory from that single snapshot.

  • valid/step_A03 — step change, amplitude A = 0.3
  • valid/sine_f40_A05 — 40 Hz sine, amplitude A = 0.5

Final test data (hidden)

Same principle as the validation set (initial snapshot + forcing signal only), used exclusively for the Final phase score. You never get direct access to this data.

  • Step change, amplitude A = 0.3
  • Step change, amplitude A = 0.5
  • 10 Hz sine, amplitude A = 0.3
  • 10 Hz sine, amplitude A = 0.5
  • 40 Hz sine, amplitude A = 0.3
  • 40 Hz sine, amplitude A = 0.5

What you will never see

The ground-truth trajectories of the validation and test simulations, and any data beyond what is described above, are never shared with participants and never available for local testing.
